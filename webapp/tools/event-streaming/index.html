Key Event Streaming Mechanics Explained

1. Append-Only Commit Logs & Offsets

Unlike traditional message queues (e.g. RabbitMQ) where consumed messages are deleted from the broker, Kafka retains messages on disk in an append-only sequential log. Consumers simply maintain an offset pointer into each partition, allowing high-throughput sequential disk I/O and arbitrary offset rewinds for replayability.

2. Partitioning & Key Routing

A topic is sharded into multiple partitions. Kafka computes hash(key) % num_partitions to assign messages with the same key (such as order_id or user_id) to the exact same partition, guaranteeing total causal ordering for that entity while enabling parallel consumption across partitions.

3. Consumer Groups & Dynamic Rebalancing

Consumers belonging to the same group coordinate partition ownership. When a consumer joins or crashes, the Group Coordinator detects heartbeat failure and triggers a rebalance, reassigning orphan partitions to remaining active members without downtime.

4. Consumer Lag & Delivery Guarantees

Consumer lag is the delta between the latest log offset produced and the current committed offset of the consumer. High lag signals downstream processing bottlenecks. Changing commit timing dictates guarantees: committing before processing causes message loss (At-Most-Once), while committing after processing causes duplicates upon crash (At-Least-Once).
