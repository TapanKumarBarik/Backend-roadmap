Design Pattern Cheat Sheet for LLD Interviews

Strategy Pattern

Defines a family of algorithms, encapsulates each one, and makes them interchangeable. Used in the Parking Lot (hourly vs. flat pricing) and Payment Gateway (Stripe vs. PayPal vs. Crypto) so clients depend only on an abstraction.

State Pattern

Allows an object to alter its behavior when its internal state changes. The object appears to change its class. Essential for the Elevator System (Idle, Moving, DoorsOpen), avoiding fragile nested if/else or switch blocks.

Factory Pattern

Decouples object creation from consumption. The client requests an implementation by key or configuration, allowing new providers or hardware types to be registered with zero modifications to existing business logic.

Relational 3NF & Junctions

Eliminates redundancy and update anomalies. Many-to-many relationships (e.g. users following users, posts tagged with multiple tags) decompose into explicit associative junction tables with composite primary keys.
