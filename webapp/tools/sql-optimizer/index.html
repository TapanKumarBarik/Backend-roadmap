Database Indexing & Query Optimization Cheatsheet

Sequential Scan vs Index Scan

A Sequential Scan reads every 8KB table page sequentially from disk ($O(N)$). When a query filters for high selectivity ($< 5\%$ of rows), an Index Scan navigates the B-Tree root-to-leaf in 3–4 seeks and reads only matching heap pages ($O(\log N)$).

The Left-Prefix Rule

A composite B-Tree index on (status, created_at) is sorted first by status, and only secondarily by created_at. A query filtering WHERE created_at >= '2026-01-01' cannot use this index as a seek because the leading prefix is missing.

Covering Index (Index-Only Scan)

When all columns requested in both the WHERE clause and the SELECT projection exist within the index leaf nodes, the engine executes an Index-Only Scan, bypassing heap table pages entirely ($0$ heap reads).

Hash Join vs Nested Loop

Without an index on foreign keys (o.customer_id), the planner falls back to a Hash Join, building a hash table in RAM and scanning all 100,000 orders. Adding an index allows the engine to perform a rapid Nested Loop Join with index seeks.
