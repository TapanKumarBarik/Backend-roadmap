Key Real-Time Connection Scaling Architecture

1. The C10K to C1000K Evolution & epoll

In traditional thread-per-connection architectures, each connection consumed an 8MB thread stack, limiting servers to ~1,000 connections. Modern non-blocking event-driven runtimes (Linux epoll, Node.js libuv, Go goroutines, Netty) monitor millions of idle descriptors on a single thread pool without context-switching penalties.

2. Socket Buffer Memory Sizing (rmem/wmem)

Every active TCP connection requires kernel receive (rmem) and transmit (wmem) ring buffers. A naive default of 128KB per socket causes 100,000 connections to eat 25GB of pure kernel memory. In production, kernel parameters are tuned (e.g. net.ipv4.tcp_rmem = 4096 87380 6291456) to keep idle sockets lean.

3. Pub/Sub Broker Backplane

Since client $A$ on Gateway Server 1 needs to chat with client $B$ connected to Gateway Server 4, gateways cannot operate in isolation. A high-throughput horizontal pub/sub backplane (Redis Pub/Sub, NATS, Apache Kafka) distributes incoming channel messages to all connected gateway nodes.

4. Reconnection Stampedes (Thundering Herd)

If a load balancer or gateway node crashes, 50,000 clients immediately attempt to reconnect in the same second, overwhelming authentication services and TLS handshakes. Clients must implement Exponential Backoff with Full Random Jitter to spread reconnection load smoothly over a multi-second window.
